# SSC With Jagrat — GK Batch Website

## What is included
- Student website
- Admin login
- Admin add/edit/delete classes
- YouTube video URL management
- Practice Sheet PDF upload
- Notes PDF upload
- Mock Test URL/HTML link
- Subject management foundation
- Supabase Auth, Postgres and Storage
- Responsive mobile design

## Setup
1. Create a Supabase project.
2. In Supabase Dashboard → SQL Editor, run `database.sql`.
3. In Authentication → Users, create your admin user (email + strong password).
4. Open `assets/config.js` and paste your Supabase Project URL and anon/publishable key.
5. Test locally with a web server (do not open index.html directly as a file). For example use VS Code Live Server.
6. Deploy the folder to a static host such as Vercel or Netlify.

## Important security note
The browser only contains the Supabase anon/publishable key. Never put a Supabase service-role/secret key in these files.

The included policies allow any authenticated account to manage content. For a true single-admin production site, restrict database/storage policies to your specific admin identity (or use a server-side admin API).

## Adding videos
Admin → Add New Class → choose "YouTube Link" or "Upload Video File".
- **YouTube Link**: paste the URL. The student page automatically converts normal YouTube watch/shorts/youtu.be URLs into an embedded player.
- **Upload Video File**: pick an mp4/webm/ogg/mov file. It uploads to the `videos` storage bucket and plays back with a native HTML5 video player on the student page. Editing a class later and choosing a new file replaces the old one (the old file is not automatically deleted from storage).

Note: direct video upload uses your Supabase storage quota (free tier is 1GB total, with a default per-file upload limit set in your project's Storage settings — raise it there if you need larger files). YouTube hosting stays free and unlimited, so it's the better default for most classes; use direct upload only for content that isn't on YouTube.

## PDFs
Select a PDF in Practice Sheet or Notes. It uploads to the `materials` bucket and stores its public URL in the class record.

## Mock tests
Paste the URL of your HTML mock test page. It opens from the student's class card.

## Installable app (PWA)
The site is now installable like an app — no Play Store needed.
- **Android (Chrome)**: visit the site → tap the ⋮ menu → "Add to Home screen" / "Install app".
- **iPhone (Safari)**: visit the site → tap Share → "Add to Home Screen".

It opens full-screen with its own icon and caches the page shell (CSS/JS/icons) so it loads instantly and still opens if the connection briefly drops — class/video data always comes fresh from Supabase when online.

**Important for hosting**: `sw.js` and `manifest.json` must be served from your site's root (e.g. `yoursite.com/sw.js`, not inside a subfolder) for install/offline caching to work correctly.

## Paid subscription system (Class 01 free, everything else needs a subscription)

**What was added:**
- `account.html` — students sign up / log in / subscribe (monthly or yearly) here.
- Class 01 of every subject is always playable for free. Every other class checks the student's subscription before showing the video/PDFs.
- Videos & PDFs are served through short-lived signed links (2 hours) generated by a Supabase Edge Function — the storage buckets are now private, so links can't be shared around to bypass payment.
- Payments go through **Razorpay** (supports UPI, cards, netbanking — the standard choice for Indian students).

### One-time setup (do this once)

**1. Run the updated `database.sql`** in Supabase → SQL Editor. It's safe to re-run the whole file even though most of it already exists.

**2. Create your Razorpay account** at razorpay.com if you haven't already (needs PAN + bank account + business KYC — this can take Razorpay a day or two to verify). Once approved:
   - Go to Settings → API Keys → Generate Key. You'll get a **Key ID** and **Key Secret**.

**3. Deploy the 3 Edge Functions** (in `supabase/functions/`) using the Supabase CLI:
```
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase functions deploy create-order
supabase functions deploy verify-payment
supabase functions deploy get-media-url
```
   (No CLI? You can also paste each `index.ts` file's code manually into Supabase Dashboard → Edge Functions → Create a new function, for each of the 3 functions.)

**4. Set your Razorpay secrets** so the functions can use them (Dashboard → Edge Functions → Manage secrets, or via CLI):
```
supabase secrets set RAZORPAY_KEY_ID=your_key_id
supabase secrets set RAZORPAY_KEY_SECRET=your_key_secret
```

**5. Set your real prices** (defaults are placeholders: ₹499/month, ₹1999/year) by running in SQL Editor:
```sql
update public.plans set amount_paise = 49900 where id = 'monthly'; -- ₹499
update public.plans set amount_paise = 199900 where id = 'yearly'; -- ₹1999
```
(amount is in paise: multiply your rupee price by 100)

**6. Test it**: Razorpay gives you Test Mode keys first — use those to run a full test payment (Razorpay's test card: 4111 1111 1111 1111, any future expiry, any CVV) before switching to Live keys.

### How it behaves
- Anyone can open Class 01 of any subject — no login needed.
- Opening any other class while logged out shows "Login to continue."
- Logged in but not subscribed shows "This is a paid class" with a Subscribe button.
- After a successful payment, access unlocks immediately (subscription checked in real time, not on next login).
- When a subscription expires, the student sees the paywall again automatically — no manual work needed from you.

## Security update v13 — required after upgrading the website

Run `database_update_v13_security.sql` once in Supabase → SQL Editor **after** the existing database migrations (v9, v10, v11 and v12).

This update:
- moves quiz scoring into the database so the browser cannot submit a forged score;
- removes quiz answer keys from public quiz reads;
- exposes only safe class metadata publicly, while uploaded videos/PDFs/mock links remain behind the existing `get-media-url` access check;
- removes `user_id` from the public leaderboard and makes student profiles private except to their owner;
- keeps quiz question management admin-only while adding edit and up/down reorder controls in the admin panel.

No new Edge Function deployment is required for these v13 security changes. The updated frontend calls the database `submit_quiz_attempt` function through Supabase RPC.

## v20 — AI Study Assistant

Added a full SSC AI Tutor for **Maths/Quant, Reasoning, English, GK/GS, and Mixed SSC**. Users can ask questions, request step-by-step explanations, generate practice sets, and request similar questions. The UI can pass a small weak-topic context from the user's existing Quiz 2.0 analytics and Mistake Book.

### Supabase setup for AI
1. Run `database_update_v20_ai_tutor.sql` after the v19 migration. This migration is additive and does not delete existing learning data.
2. Deploy the new Edge Function at `supabase/functions/ai-study-assistant/index.ts`.
3. Add the secret `OPENAI_API_KEY` in Supabase Edge Function Secrets. Do **not** put an OpenAI key in `assets/config.js` or any browser JavaScript. Supabase Edge Functions are the server-side boundary for the AI provider.
4. Optional: set `AI_MODEL` as an Edge Function secret. The bundled default is `gpt-5`; change it only if your OpenAI project has access to another supported model.
5. The frontend invokes the function as `ai-study-assistant` after the user is authenticated.

Example CLI deployment (from the project directory):
`supabase functions deploy ai-study-assistant`
`supabase secrets set OPENAI_API_KEY=YOUR_KEY`

The AI feature is intentionally fallback-safe: if the function or key is not configured, the rest of the website continues to work and the AI page shows a setup message.

### One-time push setup
1. Generate VAPID public/private keys.
2. Put the public key in `assets/push-config.js`.
3. Deploy `supabase/functions/send-push`.
4. Set Edge Function secrets: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, `PUSH_CRON_SECRET`.
5. Schedule your server/cron to POST reminder jobs to the function with `x-push-cron-secret`.
6. Users enable notifications at `notification-settings.html`.

The service worker handles push display and click routing. Paid media and answer keys are not intentionally cached by the notification feature.
